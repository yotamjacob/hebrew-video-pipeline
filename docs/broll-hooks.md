# Stock B-roll & hook generation

Deep contracts moved out of CLAUDE.md (2026-08-09) to keep the always-loaded core lean.
**Read this file fully before changing** B-roll search/scoring/validation, hook generation, or their polling/AI-resilience. Everything here is load-bearing;
update it in place when behavior changes.

**Generator polls survive backgrounding (2026-08-09)** — the hook + stock-B-roll poll loops previously died after 3 straight network failures; minimizing the app freezes the WebView and kills in-flight fetches, so a backgrounded phone showed "failed" while the job kept running (field report). Both loops now mirror `pollForJSON` semantics: server-sent errors (`err.isServer`, incl. `ai_busy:*`) stay immediately fatal, but pure network failures park on `_whenVisible()` and keep polling until a hard deadline (hook 600s, B-roll 900s). Tests: "burst of killed polls" in `broll.spec.js`, the 529 + network-blip cases in `hook.spec.js`.

**`_process_moment` is a plain function by design** — it runs in a ThreadPoolExecutor inside `analyze_stock_broll`'s container. Do NOT add `@app.function` to it: Modal Function objects are not directly callable, which silently broke all stock B-roll clip fetching until 2026-07-02.

**B-roll: 2-3s clips at the peak moment (2026-07-12)** — moment duration is clamped to **2-3 seconds** (`broll_fns.py` `_validate`, was 2-5s; Sonnet prompt guidance + examples updated to match). At burn, `_peak_window(clip_path, want_dur)` (`pipeline_fns.py`) picks the highest-MOTION `want_dur` window of the downloaded clip (ffmpeg `fps=8,scale=64,tblend=difference,signalstats` YAVG energy, sliding-window max) and overrides the pre-computed middle window — so the short insert shows the peak action. Best-effort (falls back to `add_clip_window`'s middle on any failure); free (no API). Tests: `tests/backend/test_rtl_broll.py`.

**B-roll cost cap** — stock B-roll is by far the priciest per-video feature (Haiku vision-scores clip frames per moment). `analyze_stock_broll` bounds each job with `_COST_BUDGET` (0.25) and `_MAX_CANDIDATES` (20) in `broll_fns.py` — lowered from 1.00/40 for a ~4× cut. Raising them raises cost per B-roll run; a density cap (1 moment / 8s) also limits moment count.

**Stock search two-prompt split** — `broad_search_prompt` is sent to Pexels/Pixabay (optimized for recall); `strict_eval_prompt` is sent to Haiku vision scoring only (optimized for precision). Never swap them — the stock libraries can't handle the strict prompt and return zero results.

**One-click auto B-roll + hook (2026-07-12)** — two toggles in Options (`#autoBroll`, `#autoHook`) nested under "Burn Hebrew captions" (`#captionChildren`) — both need the transcript, so they're gated on `burnCaptions` (greyed + `opt.autochild.needsCaptions` note when off; `_syncCaptionChildren()` enforces this + shows the `#autoExtraTimeNote` extra-time estimate when either is on, and audio mode hides the whole block). When toggled, `_startAutoGenerations()` (called after `showCaptionEditor()` in `run()`/`rerun()`) fires **both in parallel, in the BACKGROUND**: `startStockBrollAnalysis(caps, {background:true})` + `triggerGenerateHook({background:true})`. Background mode = skip `lockPipelineActions`/scroll/editor-freeze/confirm, and drive checklist rows `#checkBroll`/`#checkHook` (`_stepActivate`/`_stepDone`) so timers show in the processing card while the user edits captions. They only POPULATE the sections (no auto-select of a hook, no auto-add of clips) — decided with the user. Caption edits show a regenerate nudge on each section (`#stockBrollRerunBanner` already; `#hookRerunBanner` + `_maybeShowHookRerun()`/`_hookGenSignature` added to match); re-burn uses the current selection (NO auto-regeneration - too costly + would discard manual picks). Reuses existing `/generate-hook` + `/stock-broll` endpoints (no backend change). Tests: `tests/frontend/auto_extras.spec.js`.

**Anthropic API resilience (2026-07-16)** — a live 529 "Overloaded" burst failed hook + B-roll jobs with a masked error: the SDK's exceptions hold live httpx objects that Modal can't deserialize on the caller side ("Could not deserialize remote exception…"). Fixes: (1) `_anthropic_client(max_retries=5)` in `pipeline_core.py` — ALL Sonnet/Haiku call sites use it (content_fns ×2, broll_fns ×2; the proofread call passes `max_retries=5` directly) so transient 429/5xx/529 retry with SDK backoff; (2) `@_plain_anthropic_errors` decorator (pipeline_core) on `generate_hook_options`/`generate_caption_options`/`analyze_stock_broll`/`search_stock_clips` re-raises escaped SDK errors as plain `RuntimeError("ai_busy:<code>")` — picklable, so the real cause crosses Modal; (3) frontend `_friendlyGenError` maps `ai_busy`/`overloaded`/`deserialize` to i18n `err.aiBusy` in the hook + B-roll error surfaces, and the hook poll now reads the error body (it used to discard it → bare "Server error 500"). Test: hook.spec.js ("AI-overloaded failure…").

**B-roll item validation (SSRF/IDOR guard)** — `/burn` composites/fetches each B-roll item server-side, so `_broll_item_safe` (in `pipeline_core.py`) validates every item in the route BEFORE spawn, and `burn_captions_fn` re-checks at its sinks (defense in depth). Rules mirror the worker's precedence (a `video_key` wins over a URL): a local clip's `video_key` must match `_BROLL_KEY_RE` = `^broll_[0-9a-f]{32}\.mp4$` — NOTE broll clips are stored `broll_<uuid>.mp4` on the shared volume and are NOT `u{uid}__`-namespaced, so `_owned_key` can't gate them; the strict format regex is what blocks `../` traversal and cross-tenant/other-file reads. A remote clip's `download_url`/`preview_url` must pass `_is_allowed_broll_url` (https + host in `_BROLL_URL_HOSTS`: pexels.com, pixabay.com, vimeocdn.com, vimeo.com) so the worker can't be pointed at internal/metadata endpoints.
