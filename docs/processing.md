# Processing pipeline (GPU worker)

Deep contracts moved out of CLAUDE.md (2026-08-09) to keep the always-loaded core lean.
**Read this file fully before changing** transcription, silence cutting, audio-only mode, enhance/upscale, progress stages, or push notifications. Everything here is load-bearing;
update it in place when behavior changes.

**ffmpeg binary selection** — prefers Homebrew `ffmpeg-full` (`/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`) over generic `ffmpeg` because `ffmpeg-full` includes libass (needed for burning subtitles).

**CUDA fallback** — `transcribe()` tries float16 on CUDA first; auto-downgrades to int8 on CPU. No manual config needed.

**Batched Whisper decode (2026-08-09)** — the CUDA path decodes via `BatchedInferencePipeline` (`faster-whisper>=1.1`, `batch_size=8`): Silero VAD splits the audio into chunks decoded in parallel on the SAME full `large-v3` model — 2-4x faster at equal accuracy, and each chunk gets the `initial_prompt` bias. Chunk independence matches our deliberate `condition_on_previous_text=False`. Any batched failure falls back to sequential decode mid-flight (`_decode` in `transcribe`); the CPU path is always sequential. `process_video` and `burn_captions_fn` both request `cpu=8` so their ffmpeg x264 encodes get guaranteed threads (mirrored in `GPU_USD_PER_SEC`/`CPU_USD_PER_SEC` — update those if the allocations change).

**Modal warmup pattern** — `GET /warmup` fires `process_video` with `filename="__warmup__"` asynchronously to pre-warm the L4 GPU container. The real `/process` endpoint benefits on the next call.

**Whisper model cache** — first run downloads ~1.5 GB to the local faster-whisper cache; Modal uses a persistent volume so it survives redeployments.

**Web API base** — `https://yotamjacob--hebrew-video-pipeline-api.modal.run` (hardcoded in `site/app.js`).

**Prompt caching** — the Sonnet moment-selection system prompt is marked `cache_control: ephemeral`. The ~5-6k-token stable prefix is cached (comfortably above the model's minimum cacheable size); only the transcript (user message) changes per call.

**Sonnet 5 API constraints** — `temperature`/`top_p`/`top_k` are REJECTED (400) on `claude-sonnet-5`; all Sonnet call sites pass `thinking={"type": "disabled"}` instead (omitting `thinking` would run adaptive thinking, eating into `max_tokens`). Variety in hooks/captions comes from prompting, not temperature.

**Enhance video modes** — `enhance_video` on `/process` is `none | filters | esrgan` (mutually exclusive selector in Options). `filters` = `ENHANCE_VIDEO_VF` ffmpeg chain inside the existing render. `esrgan` = Real-ESRGAN `realesr-general-x4v3` as a separate tracked stage (`upscale`) after the cut: SRVGGNetCompact implemented INLINE with plain torch (basicsr is deliberately avoided — it imports `torchvision.transforms.functional_tensor`, removed in torchvision 0.17+); weights cached on the model volume; frames piped raw through ffmpeg; output up to 4× capped at 2160 short side — a true-4K master (`_upscale_target`) — plus `cas=0.4` contrast-adaptive sharpening on delivery frames; ~0.5 s/frame fp16 on the L4 (`process_video` timeout is 1800s for this; `max_containers=12` caps concurrent L4 containers so a burst queues rather than autoscaling GPU spend without bound). The GPU image installs CUDA torch (cu124) for this pass — do not switch it back to the CPU wheel.

**Push story is EXACTLY TWO messages (2026-07-16)** — per video: (1) "ההעלאה הסתיימה" fired at `process_video` start (kind `processing` — the last byte landed, deferred spawn ran), (2) one completion push — `edit_ready` (captions/B-roll flows) or `video_ready` (terminal cut-only, via `_record_job`). Same FCM `tag="hebpipe-job"` so (2) replaces (1) in the shade. The old post-burn third push is REMOVED: `_record_job(..., notify=False)` from `burn_captions_fn` (exports start inside the editor; the in-app success banner announces completion) — terminal cut-only keeps `notify=True` because for that flow `_record_job` IS the completion message. Don't add per-stage pushes back.

**Silence cutter: noise + filler rejection (2026-07-10)** — the cutter's job is to keep ONLY confident real speech; ambient noise (birds, traffic, wind) that Whisper hallucinates words over, and vocalized hesitations ("umm"/"אה"), are cut. Layered in `pipeline_fns.py`: (1) **VAD** threshold `0.5` (Silero, tuned for human voice — non-voice scores low; was `0.35`); (2) `transcribe` sets **`condition_on_previous_text=False`** (the #1 anti-hallucination lever — stops the model "talking through" noise; the Sonnet proofread restores cross-sentence coherence) plus `no_speech_threshold`/`log_prob_threshold`/`compression_ratio_threshold`; (3) **`_segments` noise gate** drops a whole Whisper segment when `no_speech_prob ≥ 0.85`, or `≥ 0.60` with `avg_logprob ≤ -1.0` (the classic hallucination combo) — its audio becomes a cut; (4) **`_is_filler`** flags hesitations (curated Hebrew+English set + tripled-letter elongation regex; deliberately EXCLUDES real words אם/הם/עם/אמא/מאה — Hebrew hesitation "אמ" uses a medial mem, distinct from the final-mem word אם), and words with `prob < 0.15` (very low bar so quiet/fast real words aren't clipped). `compute_keep_segments` now works on the FLAT word stream: silence gaps ≥ `min_sil` cut, and a `filler` word forces a TIGHT cut around its span (`EDGE=0.06`) so the "umm" audio is excised, not just hidden. **(5) VAD word-timestamp repair (2026-07-10):** the cutter is speech-driven (Whisper word gaps), but Whisper routinely INFLATES a word's span to swallow a pause — classically a trailing function word like "אם" reported [16.8,18.14] when the voice is only [18.0,18.14] and 16.8-18.0 is a room-tone pause; energy detection can't catch it (room tone ~-30dB ≈ the clip's quiet-speech level). `_repair_word_timestamps_with_vad` runs faster-whisper's bundled Silero VAD (`faster_whisper.vad.get_speech_timestamps`, voice-presence not loudness) on `clean_wav` and clamps each word to its overlapping voice region via `_clamp_word_to_speech` (leading/trailing trim only; leaves a word untouched if VAD found no overlapping voice, so quiet real words aren't destroyed). This re-exposes the hidden gap → the existing word-gap cutter cuts it, and caption timing gets accurate too. Best-effort (import/run failure keeps raw timings). Verified on the real "bad-silence-cut" clip: 9 long (≥1s) pauses → 0, text stays coherent. Fillers are also skipped in `generate_ass` so captions stay clean even when silence-cut is off. Safety: if NO confident speech survives, the whole clip is kept (never nuke everything). Tuning knobs are module constants (`_NO_SPEECH_*`, `_AVG_LOGPROB_MIN`, `_WORD_PROB_MIN`, `_FILLER_EXACT`). Tests: `tests/backend/test_silence_cutter.py`.

**Audio-only inputs (`is_audio`)** — the pipeline accepts audio files (`.ogg/.mp3/.wav/.m4a/.aac/.flac/.opus`), not just video. Frontend flags it at file-select (`_isAudioFile`, MIME/extension) and sends `is_audio=true` on `/process`; the backend ALSO auto-detects via `has_video_stream(src)` (excludes album-art `attached_pic`) so a mislabeled file still routes correctly. Audio path in `process_video`: duration from `probe_duration` (no `probe_video` v:0 select → would raise), always transcribes (captions/SRT are the point), and `render_audio` trims to keep-segments (or straight re-encodes) → **AAC in `.m4a`**, keyed `…_cut.m4a`. Output audio source = `clean_wav` when enhance-audio is on (DeepFilter, mono, loudnorm) else the untouched source. No `generate_ass` burn, no ESRGAN, no B-roll/hooks — those are hidden in the UI (`applyAudioMode` toggles `burnCaptionsRow`/`enhanceVideoRow`/`enhanceVideoPanel`). The job is always recorded (terminal, no burn follows). **`_cut.m4a` must be listed alongside `_out.mp4`/`_cut.mp4` everywhere a suffix is filtered** — `/jobs` list+DELETE, `prune_volume` fail-safe, download content-type (`audio/mp4`). Frontend: reduced caption editor (`showCaptionEditor` audio branch) = native `<audio id=cutAudio>` player + editable caption list + Download SRT (`downloadSRT`, pure-frontend) + Download audio (`downloadAudio`); no video preview/sliders/burn. History rows for `.m4a` keys show an audio glyph (no thumbnail fetch) and no schedule button (`_historyCard` `isAudio` branch). Mode is derived from the output-key extension in ALL result paths (fresh run + reload-resume) so it survives a reload where the picked File is gone. Tests: `tests/frontend/audio.spec.js`.

**Real checklist progress** — `process_video` writes real stage transitions to the `hebpipe-progress` modal.Dict (key = upload key, value = `{stage, done:{step: secs}, ts}`; stages: `enhance`, `cut`, `upscale`, `save`). **The `save` stage (2026-08-09)** covers publishing the result — volume copy + commit, plus `_record_job`/`prune_volume` for terminal runs — which can take a minute on long videos and used to read as a hang after everything showed done. The client row `#checkSave` is always listed; its label is flow-aware (`prog.saveDl` "Preparing download" when no editor follows, `prog.save` otherwise, set in `_resetChecklist`). **Cut-only done is not a dead end (2026-08-09):** `showDone()` un-greys the options card and shows `#reprocessBtn` (only when `currentUploadKey && selectedFile` — after a reload-resume the File is gone and rerun can't start), so tools can be re-picked without re-uploading. Tests: `tests/backend/test_save_stage.py`, the cut-only cases in `tests/frontend/upload.spec.js`. `GET /process_poll/{id}/?key=` includes it as `progress` while running, and the final result carries `step_times`. The site checklist shows only real numbers — never estimated splits (the old T4-calibrated fake timers are gone). Entries are popped on completion; stale ones pruned by `prune_volume()` after 6 h.
