# Frontend UI conventions

Deep contracts moved out of CLAUDE.md (2026-08-09) to keep the always-loaded core lean.
**Read this file fully before changing** the design system, footer, tab caching, celebrations, error telemetry, or frontend test conventions. Everything here is load-bearing;
update it in place when behavior changes.

**Celebration micro-interactions (2026-07-10, trimmed 2026-07-11)** — restrained, on-brand payoff. **Schedule success** (`scheduleNow`) fires `celebrateToast(text)` — a cream pill with a springy SVG check + short text ("Scheduled!"). **Export complete** (both `burnSuccessBanner` reveal sites) calls `celebrateExport()` which glow-pulses the banner, springs its check, and scrolls it into view. **Removed 2026-07-11 (user request):** the edit-ready "N captions ready" toast (both `showCaptionEditor` branches) and the export "seconds trimmed" count-up stat — `celebrateExport` now just glows/springs/scrolls and force-hides `#burnSuccessStat`; the `_countUp` helper and the `celebrate.captionsReady`/`celebrate.secTrimmed` i18n keys are gone. Helpers in `site/app.js`: `celebrateToast`/`celebrateExport`/`_pulse`/`_prefersReducedMotion`. NO confetti (chosen "restrained"), NO emoji (check is inline SVG → keeps `test_no_emoji_frontend` green). CSS classes `.celebrate-glow`/`.celebrate-check`/`.celebrate-toast[.show]` in `app.css`; the existing global `prefers-reduced-motion` block makes the keyframes instant. **The toast is reparented to `<body>` in `celebrateToast`** (z-index 10001) — inside the in-flow container it was trapped in a lower stacking context and rendered behind the sticky `.app-topbar`. i18n keys `celebrate.*`. Tests: `tests/frontend/celebrate.spec.js`.

**Footer (2026-08-08, WhatsApp removed)** — every view footer has exactly THREE actions in a symmetric single row (`repeat(3, minmax(0,1fr))` grid, identical 52px buttons): contact (opens `#contactOverlay`), legal, delete-account; the version badge spans its own centered row below. The WhatsApp feedback link + `_syncWaLink()` + `wa.*`/`footer.whatsapp` i18n keys are GONE (user request); no floating FAB either. The public contact address is the owner's gmail `hebrewpipeline@gmail.com` (footers, contact modal + `copyContactEmail`, `auth.migrationNote`, legal.html, delete-account.html) — a `contact@hebrew-pipeline.app` forwarding setup was tried and reverted same-day at the user's request (its DNS records were removed too; don't reintroduce without asking). Test: `tests/frontend/footer.spec.js` (also pins the address).

**History/Admin tab render cache (2026-08-08)** — `loadHistory`/`loadAdmin`/`loadCosts` no longer wipe + respinner on every tab open: each keeps a JSON signature of the last-rendered data (`_historySig`/`_adminSig`/`_costSig`), shows the loading state only on first load, always refetches in the BACKGROUND, and rebuilds the DOM only when the payload changed (a History rebuild refetches every thumbnail — the media token rotates so thumb URLs never browser-cache — and resets scroll). `{force:true}` (used by the `langchange` re-render) redraws even when data is unchanged since rows carry `t()` strings; the History in-place delete updates `_historySig` so the next open doesn't see a phantom change; `loadCosts` guards against a stale range response landing after a range switch (`days !== _costDays`). Errors only surface when there's no cached render. Tests: `tests/frontend/tab_cache.spec.js`.

**Error telemetry → instant admin push (2026-07-27)** — every user-facing failure surface (`showError`, hook, B-roll, burn) calls `_reportError(stage, msg)` in `app.js`, which POSTs `{stage, message, version, ua}` to `/error-report/`; the route stores it in the `hebpipe-errors` Dict (bounded to the newest 300, keyed `e:{ms}:{uid8}`) and calls `_alert_admins()` (`pipeline_core.py`) to FCM-push every admin (`role=='admin'` or `ADMIN_USERS` env) — so the owner learns about field failures as they happen. The terminal-failure branch of `/process_poll` alerts too. `GET /admin/errors` returns the newest 100 (admin-only). **`_reportError` uses a PLAIN `fetch`, never `apiFetch`** — `apiFetch` turns a 401 into `_sessionExpired()`, so reporting an error would tear the app back to the login view mid error-card (an expired session, or an older backend without the route, both 401); telemetry must never touch session state. Quota-exhausted (402 `limit_reached`) is deliberately NOT reported — it's a sales signal, not a malfunction. The `api()` function needs the `hebpipe-fcm` secret for the pushes. Tests: `TestAlertAdmins` in `tests/backend/test_asgi.py`, `tests/frontend/errors.spec.js`.

**Frontend tests must stub EVERY boot/error side-call (2026-07-27)** — `showApp()` fires `/auth/me` + `/auth/media-token` + `/oauth/status`, and any error surface now fires `/error-report`. Unmocked, these escape to the REAL api with a fake token, 401, and `apiFetch`'s `_sessionExpired()` tears the app view down mid-assertion — a race the suite wins locally and loses on slow CI runners (this was the intermittent `auth.spec.js` red: `#pipelineView` "Received: hidden"). `bootApp` stubs the boot three and `mockAllApis` stubs `/error-report`; specs that call `page.goto('/')` directly (`auth.spec.js`) stub all four in their own `beforeEach`. Playwright's LAST-registered route wins, so a test wanting a real 401 just re-registers.

**Audio-input notice (2026-07-11)** — selecting an audio file shows the `#noticeAudio` info notice ("Audio file detected — limited functionality: captions & clean audio only") set in `handleFile` when `isAudioInput`, cleared in `clearNotices()`. i18n `file.audioTitle`/`file.audioBody`. Test in `tests/frontend/audio.spec.js`.


## Site module details (moved from the module map)

| `site/index.html` | Vercel frontend markup — "פייפליין" branding (catchphrase: עריכות וידאו בלחיצת כפתור); tabs: **Create** (upload/process/download) and **History**; no framework |
| `site/app.js` | All frontend logic (upload, polling, editor, burn, debug panel, stats tab, scheduling). Metricool **connection** is an account-level topbar chip (`#metricoolChip`, `refreshMetricoolChip`) surfaced up front — when connected the chip itself is the disconnect button (confirm modal → `POST /oauth/disconnect`); **scheduling** is a shared modal (`#scheduleOverlay`, `openScheduleModal(video)`) opened from BOTH the post-burn `#openScheduleBtn` and each History row's 📅. Suggest-caption only shows for fresh videos (needs the in-memory transcript, not stored per job). |
| `site/i18n.js` | EN/HE dictionary + engine: `t(key, vars)`, `data-i18n` attrs, `setLang` (sets `dir=rtl`, persists `hebpipe_lang`, fires `langchange`); toggle button `#langToggle` in hero |
| `site/app.css` | All frontend styles. **Design system (2026-07-05, "modern boho"):** warm sand `--bg:#E8DFD3` + subtle SVG grain, cream surfaces `--white:#F4ECE0` (NO pure white, never pure black), muted earth palette — the historical `--purple-*` ramp is REPURPOSED as olive→sage→sand (primary `#7E8E6A`, nothing purple), plus semantic `--terracotta`/`--olive`/`--sage`. Accent = terracotta (CTA + logo, used sparingly). Fonts: Frank Ruhl Libre (headings, weights ≤500) + Assistant (body/UI); no mono, no Rubik. Thin-stroke (1.5) olive line-icons, **no emoji anywhere** (fully removed 2026-07-09): i18n strings are emoji-free in BOTH languages; every functional glyph is inline SVG — HTML notice/status/chevron/checklist icons, and JS-inserted ones via the `ICON` map in `app.js` (`x`/`check`/`play`/`stop`/`scissors`/`star`, sized `1em` so they inherit container font-size + `currentColor`); section titles are plain text. Enforced by `tests/backend/test_no_emoji_frontend.py` (scans `i18n.js` + `index.html`). History actions/schedule are inline SVG. Decorative layer in `.boho-bg` (fixed, z-index 0, RTL-anchored via logical insets): 2 soft organic blobs + 1 wandering terracotta contour; botanical line-art sprigs (`.botanical*`) in the hero + upload empty state. No gradients, no glassmorphism/blur, warm-tinted soft shadows. Mirrored into legal.html. |
| `site/sw.js` | Service worker — background job polling only (no asset caching) |
| `site/legal.html` | Standalone bilingual privacy policy + terms (HE default, EN toggle, shares `hebpipe_lang`); served as a real file, bypassing the SPA rewrite. **Opened in an on-page modal, not by navigation (2026-07-11):** every footer `footer.legal` link + the `auth.terms` link call `openLegalModal()` (`return false` keeps the `/legal.html` href as a no-JS fallback), which lazy-loads legal.html into the `#legalFrame` iframe inside `#legalOverlay` — so a user mid-edit never loses progress to read the policy. legal.html hides its own `#backLink` when embedded (`window.self !== window.top`). Footer `footer.contact` opens `#contactOverlay` (email mailto + Copy button) via `openContactModal()`. Both modals close on Esc / backdrop click. Helpers `openLegalModal`/`closeLegalModal`/`openContactModal`/`closeContactModal`/`copyContactEmail` in `app.js`; `.legal-dialog`/`#legalFrame` styles in `app.css`; i18n `contact.*`. Tests: `tests/frontend/legal_contact.spec.js`, `tests/frontend/footer.spec.js`. |
| `site/vercel.json` | SPA rewrite rule (all routes → index.html) |
